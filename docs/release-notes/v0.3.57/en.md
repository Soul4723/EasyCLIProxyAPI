## Fixed

- Aligned the Pi configuration page with the plugin's model catalog, filtering hidden models and validating the default model against the same list to avoid selecting models unavailable in Pi. [#527](https://github.com/router-for-me/EasyCLIProxyAPI/pull/527)
- Installing or updating the Pi plugin, or applying its configuration, now clears the old model cache so Pi fetches the latest catalog on its next start. If the cache cannot be cleared, subsequent configuration writes stop with an error.
- Fixed a build failure caused by a missing reasoning-level field in Pi model initialization while retaining existing ZCode reasoning-level support.

## Improved

- Models connected to DeepSeek Harness through CPA now default to text and image input, including custom model IDs and models without vision metadata. Reapplying the configuration updates previously generated settings while preserving manual overrides.

## Usage Notes

- After updating, reapply the DeepSeek Harness configuration and restart its App or Web service. Restart Pi after changing its configuration to load the latest model list.
- Image input settings allow the client to send images; actual vision support still depends on the selected model and upstream service.
